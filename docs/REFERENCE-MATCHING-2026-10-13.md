# Private reference matching

Open an owned project with a completed master, then import a private reference through Library. In Studio, scroll to **Reference listening room**, select the audio asset and choose **Compare reference**. These are measured comparisons, not AI-generated quality scores. No provider is required.

Expect a glass control panel with loudness, crest factor, stereo ratio and four-band balance differences. Results are saved as durable jobs together with the selected reference and source-master identifiers. A historical result remains inspectable when either changes; applying it is disabled until a new comparison is available.

**Audition matched master/reference** plays actual WAVs normalized to a shared integrated-LUFS target. The target is reduced to preserve sample headroom. Pause using the audition control or existing transport. The waveform transport reflects the selected preview; return to master playback through the existing player. Comparisons include the complete bounded audio, not arbitrarily equal-length crops. Different recordings can have different lengths.

Choose **Review adjustment** to edit the suggested gain (−12 to +12 dB) and mid/side width (0 to 2). Cancel leaves settings unchanged. **Confirm new render** saves settings into a new project revision and queues a render of the reviewed source. The original master and private reference remain unchanged. Headroom failure asks for lower gain/width rather than clipping. Activity exposes actual processing, failure, cancellation and retry. Reopen the project to check persisted settings and job results.

Suggestions compare measured loudness and mid/side RMS ratios, with bounded changes. Mono recordings cannot acquire new stereo detail. Band percentages and crest factor help listening decisions; automatic EQ, dynamics matching and professional mastering certification are outside this feature. Loudness measurements require at least half a second of non-silent audio and the installed `pyloudnorm` dependency. Missing engines, silence and invalid media produce failed jobs with actual errors.

The API adds persisted `reference: {asset_id, gain_db, width}` settings and queued `reference_analysis` / `reference_render` kinds. These jobs require the current `source_master_asset_id`, reject stale masters, validate source ownership and use existing durable cancellation/retry handling. Analysis returns `comparison`, two `audition_asset_ids` and immutable source identifiers. Public showcases include the chosen published master; reference files and comparisons are not published automatically.

Reproducible checks are `tests/test_reference_audio.py`, Flutter `test/reference_test.dart` and `tools/reference_acceptance.cjs`. Run browser acceptance only against isolated services configured as described in the existing acceptance setup; it creates explicitly illustrative fixtures, not production account data. Current acceptance results and artifact hashes are recorded in `REFERENCE-MATCHING-2026-10-13.json`.

To reproduce browser acceptance on Windows, use a new terminal with `AUREON_DATA_DIR` pointing to an unused directory beneath `.tools/` and `DATABASE_URL` set to `sqlite:///` plus its absolute `studio.db` path (forward slashes). Run `start-local.ps1` with `-PythonPort 8104 -GatewayPort 5084 -UiOrigin http://localhost:3006`. Build Flutter web with `--dart-define=API_BASE_URL=http://127.0.0.1:5084`, then serve `build/web` through `python -m http.server 3006` in another terminal. Chrome and a Playwright Node installation are required; set `PLAYWRIGHT_MODULE` to that installation's absolute module directory and run `node tools/reference_acceptance.cjs` from the repository root. Stop only those services with `stop-local.ps1 -GatewayPort 5084` after testing. Existing occupied ports are not replaced. Keep test storage separate from normal local data.
